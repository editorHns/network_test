# Отчёт по заданию «Network Test»

## 1. Цель работы

Перевести программу в сетевой режим, организовать клиент-серверное
взаимодействие и провести нагрузочное тестирование.

## 2. Реализация

Сервер реализован на C++ с использованием TCP sockets. Поверх TCP
используется простой HTTP-запрос.

Основной endpoint:

```text
GET /api/calc?a=10&b=20
```

Сервер возвращает:

```text
30
```

Дополнительный endpoint:

```text
GET /health
```

возвращает:

```text
OK
```

## 3. Сборка

Команда:

```bash
make
```

**Скриншот 1 — успешная компиляция.**

## 4. Запуск сервера

```bash
./network_server
```

**Скриншот 2 — запущенный сервер и сообщение о порте 8080.**

## 5. Проверка сетевого взаимодействия

Проверка:

```bash
curl "http://127.0.0.1:8080/health"
```

Результат:

```text
OK
```

**Скриншот 3 — проверка health endpoint.**

Основная операция:

```bash
curl "http://127.0.0.1:8080/api/calc?a=10&b=20"
```

Результат:

```text
30
```

**Скриншот 4 — клиентский HTTP-запрос и ответ сервера.**

## 6. Отдельный клиент

Запуск:

```bash
python3 client/client.py
```

Ожидаемый вывод:

```text
HTTP status: 200
10 + 20 = 30
```

**Скриншот 5 — работа клиента.**

## 7. Нагрузочное тестирование

Для нагрузки используется k6.

Команда:

```bash
k6 run loadtest/network_test.js
```

Конфигурация теста:

- 20 виртуальных пользователей;
- длительность 30 секунд;
- HTTP GET к `/api/calc`;
- проверка HTTP 200;
- проверка тела ответа `30`;
- threshold ошибок `< 1%`;
- threshold p95 `< 500 мс`.

**Скриншот 6 — итоговый отчёт k6.**

## 8. Результат

В результате создано клиент-серверное приложение. Сервер принимает
сетевые HTTP-запросы через TCP socket и возвращает результат обработки.
Отдельный клиент успешно взаимодействует с сервером. Нагрузочное
тестирование выполняется автоматически с помощью k6.

Фактические значения RPS, latency и количества запросов фиксируются
по результатам реального запуска k6.
